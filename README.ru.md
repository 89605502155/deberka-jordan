# jordanplan

Планы перераспределения общего ресурса по разложениям Хана и Жордана.

Библиотека рассматривает цикл перераспределения между потребителями общего
пула как знакопеременную меру. Пул — это память хоста под виртуальные машины,
квота CPU, полоса пропускания или бюджет. Из меры строятся три вещи.

1. **План наименьшего объёма.** Разложение Жордана сводит все предложения
   цикла по потребителям. Объём операций равен нижней границе
   W = Σ|a′ᵢ − aᵢ|.
2. **Безопасный порядок.** Сначала доноры, затем получатели. Пул не уходит
   в минус даже при медленном исполнителе и при доноре, который отдал не всё.
3. **Индекс колебаний и порог нечувствительности.** Мера скачков на оси
   времени даёт κ = 1 − |ξ(W)| / |ξ|(W). Перебор порога h выбирает наименьший h
   с κ не выше цели. Число операций при этом не больше V/h.

Ядро написано на чистом Python без зависимостей. Модуль для баллона KVM через
libvirt устанавливается отдельно.

## Установка

```bash
pip install jordanplan-deberka            # ядро
pip install "jordanplan-deberka[kvm]"     # + libvirt
```

Python 3.11–3.14. Имя для импорта — `jordanplan`.

## Модули

| Модуль | Что внутри |
|---|---|
| `measure` | `SignedMeasure`: мера множества, полная вариация, разложения Хана и Жордана |
| `plan` | `jordan_plan` (порог, границы, дележ нехватки), взаимозачёт `netting_report`, `netting_by_cycle` |
| `order` | порядки `two_phase`, `recipients_first`, `shuffled`, `pairwise`, траектория пула |
| `execute` | протокол `Backend`, модель `RateLimitedSim`, исполнители `execute_two_phase`, `execute_simultaneous` |
| `churn` | индекс κ, вариация, граница V/h, повтор контроллера `replay_reserve`, перебор `deadband_sweep`, `choose_deadband` |
| `kvm` | `LibvirtBackend`: баллон доменов libvirt, свободный пул по MemAvailable |

## Командная строка

```bash
jordanplan plan state.csv --pool 100 --deadband 64     # consumer,current,target
jordanplan net proposals.csv --out netting.csv         # cycle,source,recipient,amount
jordanplan deadband trace.csv --interval 2 --reserve 256 --h 0,32,64,128 --out sweep.csv
```

Журнал предложений контроллера можно подать в формате
`cycle,donor,recipient,amount_mib`. Трасса — колонка `t_s` с равномерным шагом
и по колонке на потребителя.

## Утверждения

| № | Утверждение | Код |
|---|---|---|
| 1 | Любая последовательность операций из a в a′ имеет объём не меньше W = Σ\|ν({i})\|. План Жордана её достигает. | `jordan_plan`, `netting_report` |
| 2 | Если пул неотрицателен до и после цикла, порядок «доноры, затем получатели» держит его неотрицательным в любой момент. | `two_phase`, `execute_two_phase` |
| 3 | При цели d + s, пороге h и s ≥ h число скачков не больше V/h, объём не больше V. | `replay_reserve`, `cycles_bound` |

Все три утверждения проверяются тестами со случайной генерацией входов (hypothesis).

## Где библиотека полезнее всего

- Контроллер выдаёт попарные передачи, и одна ВМ в цикле бывает и донором,
  и получателем. Взаимозачёт убирает транзитный объём.
- Свободный пул мал, а баллон надувается медленнее, чем сдувается.
  Двухфазный исполнитель выдаёт получателям только фактически освобождённое.
- Выделения колеблются туда и обратно. κ это измеряет, а перебор h находит
  компромисс между числом операций и дефицитом.

Если контроллер сразу выдаёт итоговые цели и пул большой, зачитывать нечего
и любой порядок безопасен.
